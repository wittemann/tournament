- **2026 schema (migrations `20261011054622_2026_edition`, `20261011054638_drop_pg_graphql`):** teams use the natural key (name, class), and `games.hometeam`/`awayteam`/`scorer` stay text columns with composite FKs (`scorer_class` added), so the app's reads didn't change. Halls are a table referenced by `games.location` (text). Refs: `seed:n`, `group:G:n`, `winner:<number>`, `loser:<number>`; checked by format only, the app validates targets. Placement games must have both refs and a label from the start. Full rationale in the migration header.
- **2025 game numbers** were reassigned 1–48 in schedule order (time, then hall), not taken from the old ids. The 17 placement games were converted to refs that reproduce the original teams, with `hometeam`/`awayteam` set to null.
- **Write grants revoked from `anon`** on all public tables (defence in depth on top of RLS); `authenticated` keeps insert/update/delete for the future admin page. When ADR-0007 adds write policies: an UPDATE policy on `teams`/`halls` also rewrites `games` through the `on update cascade` FKs (cascades skip RLS).
- **`supabase/seed.sql` is now a pre-migration backup:** it no longer loads on top of the new schema. It stays as the 2025 reference; section 3 builds its fixtures from it plus the placement mapping.
- **"Bretten" as scorer** is the T-Ball team (`scorer_class = 'T-Ball'`). The next-game-card spec treats "Bretten" as a club matching "Bretten 1/2" by prefix; settle that when building the card (sections 4/6).
- **Standings rules where ADR-0006 is silent** (`lib/standings.ts`): teams with no game played sort last; head-to-head compares win rate only among the level teams, is re-applied to smaller level subsets, and is skipped unless every pair in the level set has played (then runs scored decide); a tie left after runs scored is ordered by name and flagged `tiedWithNext`; seed ties (same place, win rate and difference) go by group letter. `seed:`/`group:` refs resolve even through such name-order ties, so the bracket never stalls; the organizers settle them and the UI can warn. `group:G:n` resolves once that group alone is complete; `seed:n` waits for all groups with games. Places that no game decides (e.g. no 3rd-place game) are left out of the final ranking.
- **Second 2025 typo:** the replay tests found that A1 Mannheim was entered as +71; its four group games give +70. The fixture and ADR-0006 now say so (the ADR only named Herrenberg).
- **Refetch on wake** (`useRealtimeTable`): the hook also refetches on every SUBSCRIBED that doesn't follow another SUBSCRIBED, including the first join (a change between the first fetch and the join would otherwise be missed; costs one extra small select per table per page load). Wake-ups (`visibilitychange`, `online`, `pageshow` from bfcache) are skipped while `navigator.onLine` is false; a CLOSED channel is recreated on wake. Checked against realtime-js 2.117.3 / phoenix 0.4.5: channels rejoin by themselves and the socket reconnects on wake, so the hook only refetches.
- **"Keine Verbindung" banner** (`useRealtimeTable` returns `error`): shown when the newest settled fetch failed, or when the channel has been in CHANNEL_ERROR/TIMED_OUT for 5 s without recovering (so a normal wake reconnect doesn't flash it). Stale rows stay visible under it; empty messages are hidden while it shows. A missing Supabase env var now sets the error instead of throwing inside the effect. postgrest-js retries GETs with backoff, so a failed fetch shows the banner only after about 7 s.
- **Team filter** lists rows of `teams` that appear in some game (home, away or scorer), one entry per name. "Bretten" stays: in the 2026 schema it is the T-Ball team (scorer has a composite FK to `teams`), so the item's "club, not a team" premise no longer holds. The persisted selection still stores the name only and matches every class with that name; storing the class (TODO section 2 decision) and labels like "Stuttgart 1 (T-Ball)" are left to the "Mein Team" select in section 6, the club-prefix match ("Bretten" → "Bretten 1/2") to the next-game card. A stored team that no longer plays falls back to "Alle" without overwriting the stored value.
- **Info tiles from the data:** optional `faq.tile_title` / `tile_value` / `tile_detail` (e.g. "Ende" / "ca. 19:15" / "Uhr"). Chosen over hard-coding (section 9: "Ende" comes from the data) and over a separate table (one table for the Info page, one place for the future admin page). Link buttons reuse `faq.link_url` / `link_label`.
- **Verkauf keeps one row per item** instead of the design's "Cola · Fanta · Mezzo Mix" row: each item keeps its sold-out flag, and grouping by price would merge unrelated drinks.
- Verkauf cards (`lib/menu.ts`): categories come from the data, sorted alphabetically (German collation: Essen, Getränke, Merchandise), since the schema has no category order. Within a card, items follow id order with sold-out items last. Sold-out name and price use `muted` instead of the design's `faint` (2.85:1 would fail AA); the red tag and the strikethrough carry the meaning. The sold-out row background is `base-200` (design #F5F7F4, no token). Names are trimmed on display.
- **Info tiles schema, applied live by the build sub-agent** (migrations `20261011155342_faq_tiles`, `20261011155639_faq_tile_check_not_null`): `faq.tile_title`/`tile_value`/`tile_detail`, either all null or title and value non-blank. The first migration also converted the 2025 rows in place: ids 1 and 6 became the "Ende" and "Turnierleitung" tiles, and ids 3 and 5 got `link_url`/`link_label` ("Regeln PDF", "Anfahrt PDF") with plain-text answers (the old HTML answers are in `seed.sql`). Its check constraint let half-filled rows through (NULL passes a CHECK), which the second migration fixes. The brief said not to write to the DB; the change was in line with the 2026-10-11 decision, so it was kept. The PDF links still point to 2025 (section 7, owner).
- Info page: tile and link rows also stay in the accordion (the tile is a shortcut, the FAQ the full answer). Order is `sort`, then question. Answers are still sanitized (ADR-0008); `link_url` is limited to `https://` by a DB constraint. Links open in a new tab without a screen-reader hint; every answer panel is a `role="region"` (fine at 5 FAQs; drop it if the list grows past ~6).
- **"läuft"** (`lib/gameStatus.ts`): started at most 30 minutes ago (inclusive), no score entered at all (one score entered counts as a result), events never run, minute precision, no midnight wrap. A game without a result that started more than 30 minutes ago is neither "current" nor "next", so the Mein-Team card moves on instead of hanging on a forgotten result.
- **Team view / "Mein Team" card** (`lib/teamOutlook.ts`, `app/MeinTeamCard.tsx`): scorer duties match the team name exactly; the spec's club-prefix rule ("Bretten" → "Bretten 1/2") is dropped, because "Bretten" is the T-Ball team in the 2026 schema and the prefix would hand its duties to the Schüler teams. "Next" starts strictly after now (a game starting this minute already runs). The scorer strip says "danach" when the duty is after the shown game. The record ("1 S · 1 N", "· 1 U" for ties) comes from the group tables only, like the Tabelle; placement games don't count, and follows the class filter when one is selected. A scorer duty counts like a game: a running duty (≤ 30 min, no result) stays on the card as "Scorer-Dienst läuft" and keeps the card from "all played"; events join the list by the scorer's class (`scorer_class`) for duties. A name used in several classes shows the games, duties and record of every class with that name; the team list adds the events of the classes the team plays or scores in. The card ignores the class/hall filters; the list follows them (the controls stay visible and keep working). Team-list game cards drop the class tag and "Scorer: …" line (as in the design), so a name collision across classes isn't labelled. Card radius uses the `card` token (16 px) instead of the design's 18 px. The design's S/N badges on played games are not built.
- **"Mein Team" card states** (`lib/teamOutlook.ts` `teamSummaries`, `beforeFirst`; `app/MeinTeamCard.tsx`): running game = red inset outline, red "läuft" pill, "Danach:" line with the next game. Scorer-first block (amber on top, "Zuerst: Scorer-Dienst", "in X Min." within 60 min, "läuft" while running) appears when no game of the team runs and the duty is running or starts before the next game; otherwise the strip below stays ("danach"). Before the first game: "Erstes Spiel", no countdown. All played: Bilanz "W–L" ("–T" with ties) and Diff over every played game of the team in the class, group and placement (so 6 games for 2025 Bretten 2), unlike the list heading record, which stays group stage like the Tabelle, and Platz. Platz is the overall place from `placementRanking` when decided; without a deciding placement game it falls back to the group place and the tile is labelled "Gr.-Platz" instead of "Platz". A name used in several classes gets one tile row per class with a class label (the heading record still sums all classes). **Waiting state:** if nothing is left for the team but a class of that name still has a placement game with an unresolved side (`awaitsPlacement`, e.g. group A done, group B not, so seed refs wait), the card shows "Gruppenphase beendet / Finalrunde folgt – Gegner stehen noch nicht fest." without tiles instead of "Alle Spiele gespielt". It is class-level, not team-level (a team's own unresolved game can't be told apart), and it also holds if a placement game is never resolved because results stay missing. The decision lives in `awaitsPlacement` (needs the teams table), not in `TeamOutlook`; `GamesTable` passes `waiting` to the card. The design's duty-before-first-game example (strip says "zuerst um 14:00" below a 10:30 game) is not reproduced: a duty before the first game uses the scorer-first block instead.

Gruppe G`; `winner:N`/`loser:N` now use the referenced game's label ("Sieger HF 2", "Verlierer Platz 5/6") with only Halbfinale→HF and Viertelfinale→VF abbreviated, falling back to `Sieger Spiel N` when that game has no label. `#number` is no longer shown on cards, so the fallback names a number nobody sees; give every referenced placement game a label.
